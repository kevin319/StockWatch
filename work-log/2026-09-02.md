# 2026-09-02 工作紀錄

## 概要

診斷 Docker Desktop 升級後服務反覆崩潰問題，並為 StockWatch 加入 HTTPS（Caddy 反向代理 + Let's Encrypt 自動憑證）。

---

## 1. Docker Desktop 反覆崩潰診斷

**現象：** Docker Desktop 重啟後幾分鐘內 daemon 自動停止，所有容器隨之不可用。

**根因：** Docker Desktop 升級至 v4.89.0 後新增 Docker AI Agent 等服務，記憶體消耗增加。機器 16GB RAM 不足以支撐，macOS 記憶體壓力過大時將 Docker VM monitor 以 `signal: killed` 殺掉。

**log 證據：**
- `com.docker.backend.log`：大量 `event streamer: error: EOF`，最終 `monitor exited: signal: killed`

**修法：**
- `settings-store.json` 新增 `"memoryMiB": 4096` 限制 Docker VM 記憶體上限為 4GB
- `"EnableDockerAI": false` 關閉不需要的 Docker AI 功能以節省資源

## 2. HTTPS 反向代理設定

**需求：** 透過 `https://mystock.investforlife.fun:8000` 存取 StockWatch。

**架構：** 既有 Caddy 容器（ArtifactsViewer 專案）已服務其他站點，新增 StockWatch 路由。

```
外部 :8000 (HTTPS) → Caddy → stockwatch-stockwatch-1:8000 (Docker 內部網路)
```

### 改動

**`/Volumes/SSD_1TB/git/ArtifactsViewer/Caddyfile`：**
- 新增 `mystock.{$DOMAIN}:8000` 區塊，反向代理到 `stockwatch-stockwatch-1:8000`

**`/Volumes/SSD_1TB/git/ArtifactsViewer/docker-compose.yml`：**
- Caddy 容器 ports 新增 `"8000:8000"`

**`/Volumes/SSD_1TB/git/StockWatch/docker-compose.yml`：**
- 移除 `version: '3.8'`（已 obsolete）
- `stockwatch` 服務 `ports: "8000:8000"` 改為 `expose: "8000"`（不再對 host 開放，由 Caddy 代理）
- `stockwatch` 服務加入 `caddy_net` 網路（`artifactsviewer_default`），讓 Caddy 能透過 Docker 內部 DNS 連線
- 新增 `networks.caddy_net` 宣告（external, name: artifactsviewer_default）

### 憑證

Caddy 自動透過 Let's Encrypt HTTP-01 challenge 取得 SSL 憑證，自動續期。

**Router port forward 需求：**
- 80 → 本機:80（ACME challenge + 憑證續期）
- 8000 → 本機:8000（HTTPS 服務）
